Pet projects

After-hours work, mostly about running my own life and my own agents as operated systems. All three have code you can read.

agent-control-plane Python · SQLite

Kubernetes-style governance for AI agents. One process, one SQLite file, no infra deps: per-task-class SLOs, multi-window burn rates, error budgets and hard caps — plus a cross-model judge that scores outputs without sharing the agent's blind spots, outcome-derived verdicts that can retroactively flip a "pass" to "fail", sealed tools behind a single deny-by-default gateway, and an Earned Autonomy Gradient where autonomy is a budget the agent spends, auto-contracting on burn and only promoting with an operator signature.

agents on-call triage, as a skill

An SRE on-call triage agent packaged as a Claude Code skill: an alert goes in, a structured investigation comes out. Retrieval is pushed into subagents so the main loop keeps only judgment, every state-changing action passes a deterministic gate, and the knowledge base compounds with each case investigated.

context-engineering personal AI workspace

The public slice of the workspace my agents live in. Model capability is a given; what you can change is what it sees. So the question is not how to write a better prompt, it is how to organise a repo so that any session starts with exactly the layer it needs. Three-layer memory, with the global constraint layer small enough to load every time and specific enough to change behaviour, plus axioms distilled from real experience and indexed by trigger rather than by topic.

Its most useful application so far is a goal-versus-behaviour loop: Anki already logs what I actually studied each day, so a deterministic engine reads that log and replaces "I think I'm studying in a balanced way" with "you haven't touched listening in three days," then proposes the cheapest way back. Anki is just the first sensor.

agent-control-plane Python · SQLite

给 AI agent 的 Kubernetes 式治理。一个进程、一个 SQLite 文件、零基础设施依赖：按任务类分的 SLO、多窗口燃烧率、error budget 与硬上限 —— 外加一个不与 agent 共享盲区的跨模型 judge、能把「通过」追溯翻成「失败」的结果导出判定、藏在单一 deny-by-default 网关后面的 sealed tools， 以及一条 Earned Autonomy Gradient：自主性是 agent 花出去的预算，燃烧时自动收缩，只有拿到操作者签名才升级。

agents oncall 分诊，做成 skill

一个做成 Claude Code skill 的 SRE oncall 分诊 agent：告警进去，结构化调查出来。检索推进子 agent，主循环只留判断； 所有会改变系统状态的动作都过确定性门；知识库随每次调查累积。

context-engineering 个人 AI 工作区

我那些 agent 住的工作区的公开切片。模型能力是给定的，能改的是它看见什么，所以问题不是怎么写一句更好的 prompt， 而是怎么组织一个仓库，让任意一次 session 开始时看见的正好是该看见的那一层。三层记忆：全局约束层要小到每次都能全量加载， 又要具体到能改变行为；加上从真实经历提炼的 axioms，按触发词索引而不是按主题索引。

目前它最有用的一个应用是「目标 vs 行为」的闭环：Anki 本来就记录了我每天真正学了什么，于是一个确定性引擎读那份日志， 把「我觉得我在均衡地学」换成「你三天没碰听力」，并给出拨回正轨最省力的那条路。Anki 只是第一个传感器。
