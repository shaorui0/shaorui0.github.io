0. Context and architecture

The page above shows the loop as an animated model, so I will not redraw it. In short: the iPhone has one button; audio goes to a FastAPI service on my Mac, is transcribed by a local Whisper, and each recording becomes one text file in daily_records/. A triage agent fixes slips, splits topics and files each piece where it belongs. What is filed lives in contexts/ (memory) and rules/, which every new session reads first. A nightly observer and a weekly reflector watch the work, and patterns that hold are promoted back into the rules. The recorder is the boring part. The product is what the next session starts with.

1. Capture with zero friction

Problem. Every extra step in a note-taking tool lowers how often I use it. Choosing a category or naming a note is exactly the step that makes me skip the thought.

What I did. One button, one input, one output: one recording is one plain text file named by start time, with only the transcript inside. No title, no tags, no metadata. The phone cuts audio into 60-second AAC chunks and keeps them in a queue until the server confirms receipt, so a killed app or a lost network drops nothing. The same recorder exists as a Mac menu-bar item.

Evidence. In daily use since the v1 release (README status dated 2026-10-12). The export contract (one recording, one file, transcript only, same-minute files get a suffix) is covered by 6 deterministic tests added in change c0002. The repo test suite is 212 passed and 1 failed (c0002 evidence); the failure is a renamed function in a test I did not touch, not caused by that change.

2. Transcription that stays on my machine

Problem. These are unfiltered thoughts, including work-adjacent ones. I did not want the audio on someone else's server.

What I did. Audio goes only to my own Mac over the same Wi-Fi or a phone hotspot, checked by sha256 and a bearer token. Transcription runs locally (silero VAD, then mlx Whisper; the ASR layer is pluggable). Three rules are written down as invariants: audio is the source of truth; a transcript is a derived file that can be recomputed; a transcript is never overwritten (a new model writes a new file). A leak scan (tools/check_rules.py) keeps home paths and personal data out of the public repo.

Evidence. The invariants are in docs/METHOD.md with the file that enforces each one. Honest scope: audio and Whisper are local, but the later steps (proofreading, the daily digest, task synthesis) send transcript text to a Claude model through the CLI. Local means the speech-to-text, not the whole pipeline.

3. Lossless topic sorting and routing

Problem. A day of speech mixes work, ideas, errands and background noise. A summary would be easy but would drop details I later need.

What I did. Triage runs in three steps. First, proofread against a glossary and my own topic list, labeling each paragraph (task, thinking, diary, small talk). Second, sort into at most 8 topics without compressing or rewriting, plus a fixed noise topic for train announcements and other people's voices, kept because lossless means lossless. Third, route each topic to its home, such as an existing decision document, a project directory or a memory file, appending only, never rewriting. A coverage check has to pass before anything is written. It produces a to-do list and a list of things I must confirm. I run it on demand, because it costs tokens and writes to the knowledge base.

Evidence. The procedure is two skills, aha_daily_triage and aha_daily_digest, plus a per-day OpenSpec change that holds the sorted originals next to the landing notes. No accuracy figure for routing exists; I have not measured it.

4. The flywheel: the workspace is code

Problem. An agent that starts each session blank makes me repeat who I am and what I decided.

What I did. The workspace itself is built like a codebase. Memory has three layers: L3 is rules/, loaded passively at every session start; L1 and L2 are contexts/memory/, which the agent searches when needed. A nightly observer and a weekly reflector (run by cron through the Claude CLI) read what changed and write observations; the reflector's prompt promotes patterns that keep holding into rules/. Every change to the Aha repo is one OpenSpec change, with raw test output, a report and one row in docs/PROCESS.md. The generic version is public as shaorui0/context-engineering.

Evidence. Observer and reflector run on schedule. The status table in docs/METHOD.md section 1 says which links run and which are only direction.

Boundaries

  • Today the link from voice to long-term memory runs through triage, which I start by hand. The observer sees that a voice file appeared, not what it says.
  • Nothing yet detects the same idea repeated across days, and a spoken follow-up does not close an earlier task automatically.
  • The reflector does promote patterns into rules, but I have not measured how often.
  • Upload works only on the same network; away from home, chunks queue on the phone. Free Apple signing expires every 7 days and needs a cable to reinstall.
  • ASR accuracy on real speech is not evaluated; the benchmark used synthetic speech. Battery drain and all-night recording are still to be measured.

0. 背景与架构

上面的页面已经用动画模型把这条循环演示了一遍，这里不再重画。简单说：iPhone 上只有一个按钮；音频传到我 Mac 上的 FastAPI 服务，由本地 Whisper 转写，每段录音变成 daily_records/ 里的一个文本文件。整理 agent 负责纠错、分 topic，并把每块内容放到它该去的地方。放进去的东西落在 contexts/（记忆）和 rules/，每个新 session 开头先读它们。每晚的 observer 和每周的 reflector 观察工作过程，站得住的 pattern 会回灌进 rules。录音器是最无聊的部分，产品是下一个 session 开始时手里拿着的东西。

1. 零摩擦的采集

问题。 记录工具里每多一步，我用它的次数就少一截。选分类、起名字，恰恰是让我放弃记下想法的那一步。

我做了什么。 一个按钮、一个输入、一个输出：一段录音就是一个按开始时间命名的纯文本文件，里面只有转写文字，没有标题、标签、元数据。手机把音频切成 60 秒的 AAC 分片，服务器确认收到之前一直留在队列里，所以 App 被杀或断网都不丢。Mac 菜单栏上也有同一个录音器。

证据。 v1 发布后日常在用（README 状态日期 2026-10-12）。导出契约（一段录音一个文件、只有转写、同分钟加后缀）由 c0002 里新增的 6 个确定性测试覆盖。仓库测试套件是 212 通过、1 失败（c0002 evidence）；那个失败是我没碰的测试里一个被改名的函数，不是这次改动造成的。

2. 留在我机器上的转写

问题。 这些是没过滤的想法，里面有和工作相关的。我不想让音频落到别人的服务器上。

我做了什么。 音频只发到我自己的 Mac，走同一个 Wi-Fi 或手机热点，用 sha256 和 bearer token 校验。转写在本地跑（silero VAD，然后 mlx Whisper；ASR 层可替换）。三条写成了不变量：音频是事实来源；转写是可以重算的派生文件；转写永不覆盖（换模型就新增文件）。一个泄漏扫描（tools/check_rules.py）保证家目录路径和个人数据不会进公开仓库。

证据。 这些不变量写在 docs/METHOD.md，每条都标了由哪个文件来强制。说清范围：音频和 Whisper 是本地的，但后面的步骤（纠错、日报、任务合成）会通过 CLI 把转写文字发给 Claude 模型。本地指的是语音转文字这一步，不是整条流水线。

3. 无损分 topic 与落地

问题。 一天的话里混着工作、想法、杂事和背景噪音。写成摘要很容易，但会丢掉我以后要用的细节。

我做了什么。 整理分三步。先对照词表和我自己的 topic 清单纠错，给每段打标签（task、thinking、diary、smalltalk）。再分成最多 8 个 topic，不压缩、不改写，另外固定一个噪音 topic 放电车广播和旁人说话，因为无损就是无损。最后把每个 topic 路由到它的去处，比如已有的决策文档、项目目录或 memory 文件，只追加，不重写。写入之前覆盖率检查必须通过。它还产出一份待办清单和一份需要我确认的清单。我按需手动触发，因为它耗 token 而且会写知识库。

证据。 流程由两个 skill 承载：aha_daily_triage 和 aha_daily_digest，外加每天一个 OpenSpec change，里面放分好的原文和落地记录。路由没有准确率数字，我没测过。

4. 飞轮：工作区本身就是代码

问题。 每次从空白开始的 agent，会让我反复交代我是谁、我定过什么。

我做了什么。 工作区本身按代码库的方式搭。记忆分三层：L3 是 rules/，每个 session 开头被动加载；L1、L2 是 contexts/memory/，agent 需要时主动检索。每晚的 observer 和每周的 reflector（cron 通过 Claude CLI 跑）读取改动并写观察；reflector 的 prompt 会把反复成立的 pattern 提升进 rules/。Aha 仓库的每个改动都是一个 OpenSpec change，附带原始测试输出、报告和 docs/PROCESS.md 里的一行。通用版本公开在 shaorui0/context-engineering。

证据。 observer 和 reflector 按计划运行。方法文档的状态表在 docs/METHOD.md 第 1 节，如实标了哪些在跑、哪些只是方向。

边界

  • 目前语音到长期记忆这一环要经过整理，而整理是我手动触发的。observer 只知道有语音文件出现，不知道里面说了什么。
  • 还没有东西能发现同一个想法跨天重复，口头的跟进也不会自动关闭之前的任务。
  • reflector 确实会把 pattern 提升进 rules，但提升率我没测过。
  • 上传只在同一个网络下工作；离开家，分片在手机上排队。免费 Apple 签名每 7 天过期，重装要插线。
  • 真人语音的 ASR 准确率没评测，benchmark 用的是合成语音。耗电和整晚长录还没实测。
